# worldmonitor

每天 07:15 生成一份四分区新闻速报（800–1200 字），通过飞书私聊发送**全文**，并存档为当日飞书文档；同日追加一份单条深度解码。

> **这个仓库不运行代码。** 它保存的是**规格** —— 这份日报按什么规则生成。
> 真正的执行体是云端定时任务里的 query。这里没有抓取管道，也没有 `python scripts/monitor.py` 这种用法。

---

## 每天产出什么

| 产物 | 时间 | 渠道 |
|---|---|---|
| 速报全文 | 07:25 前必达 | 飞书私聊（正文即全文，不是摘要） |
| 速报存档 | 07:25 前 | 飞书在线文档，当日新建 |
| 单条解码 | 07:25 前 | 独立飞书文档，不单独推送，链接随速报一起发出 |

---

## 结构：四分区

顺序固定，不随当天新闻权重调整：

```
1. 国内外时政
2. 社会民生
3. AI 与前沿科技（末尾固定子块「开源」）
4. 全球经济与产业（末尾固定免责声明）
```

- 分区内按重要性降序；**块间不设条数上限** —— 当天哪个领域重，那个块就长。
- 总条数 10–15（不含开源子块）。
- 不设「每分区 2–3 条」的硬均衡。均衡是给多读者日报用的，这里只有一个读者。

---

## 几条最要紧的规则

完整规则见 **[SPEC.md](SPEC.md)**，此处只列会被违反得最频繁的几条：

- **单条两段**：事实一句（主体 + 动作 + 关键量 + 来源）+ 评价一句（影响/趋势/关注点/风险，只选一个角度），不许合成一句。
- **「今日核心关注」放开头**，是指路牌不是总结 —— 当天最重的一条可能排在第 4 位，只有这句话能把它提到眼前。
- **篇幅硬顶 1200 字**。扩容只允许两类理由：重大事件需多条跟进、开源有重磅 Release。「今天条目多」不是理由。
- **无确数用定性词**。金额、涨幅、人数、星数、排名，凡没把握的精确数字一律写「大幅」「数千万级」「周增数千星量级」。宁可模糊，不可编造。
- **每条必须带指向事件本身的链接**（不是搜索页、不是聚合首页）。
- **开源 0–2 条，宁缺毋滥**。`awesome-*` 索引类仓库不算项目；当天没有够线的，整块省略。

## 仓库结构

```
worldmonitor/
├── SPEC.md                      # ★ 唯一规格真相源：日报按什么规则生成
├── README.md                    # 本文件：入口与导航
├── config/
│   └── sections.yaml            # 四分区 → 关键词映射（仅用于归类与查漏）
└── .github/
    └── workflows/
        └── daily.yml            # 仅手动触发：口径巡检，不做定时
```

**没有的东西也是设计的一部分**：没有 `scripts/`（不跑抓取）、没有 `requirements.txt`（无依赖）、没有 `templates/daily_report.md`（模板只保留 SPEC.md §10 一份，避免两处漂移）。

## 口径真相源

`SPEC.md` 是唯一真相源。改口径的**唯一正确顺序**：

1. 改 `SPEC.md`，commit 里写清改了什么、为什么；
2. 再改云端任务 query，只 patch `query` 字段，不动 schedule / title / enable；
3. 手动跑一次验证；
4. 在 commit message 里记一行结果。

**顺序颠倒就会漂。** 本仓库曾经漂过一次：README 和 `config/sections.yaml` 停在早期五板块口径，而生产早已改成四分区 —— 原因就是先改执行、后改文档。

## 私有信息边界

以下内容**不进本仓库**，只在运行时由执行方提供。仓库里最多出现字段名：

- 读者的职业、关注行业、风险敞口、常驻地区
- 飞书 `open_id` / `chat_id`
- 任何 token、cookie、密钥

## 明确不做

| 不做 | 原因 |
|---|---|
| 抓取管道（微博/知乎/百度/抖音热搜） | 与「社交平台仅采信官方账号」冲突，且无此需求 |
| GitHub Actions 定时生产 | 与云端任务职责重复，早期示例长期失败，已改为仅手动 |
| 接入 GDELT / ACLED / AIS / ADS-B 等数据源 | 从未接入，任何「已接入」表述都是不实描述 |
| 多读者适配、板块均衡 | 只有一个读者 |
| 全量事实核查（逐条 fetch 原始源） | 延迟 10–15 分钟、提高断更概率，收益低于「写法约束」 |

## 口径演变

- **早期**：五板块长日报，每板块 5–8 条，每条 2–3 句深度评价，含「今日重点关注」。
- **中期**：压成四板块、中立客观、300–500 字；增补 GitHub 开源信源规则。
- **现行（v2.0，2026-11-05 起）**：四分区、事实一句 + 评价一句、800–1200 字、开源 0–2 条、07:25 必达。

保留这段是因为：翻旧 commit 的人需要知道**为什么变了**，否则容易把历史写法当成目标。
